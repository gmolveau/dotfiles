# macOS first install — Ansible

## Ansible in 2 minutes

- **Playbook** (`macos-first-install.yml`) — the entrypoint; declares which
  machines to configure (`hosts: localhost`) and which roles to apply.
- **Role** — a reusable unit of configuration. Here: `macos_first_install`
  (system tweaks) and `dotfiles` (bare-repo checkout + zsh plugins).
  Each role contains:
  - `tasks/` — the steps to converge; each step is a **task**;
  - `defaults/` — variables with low precedence, easy to override;
  - `vars/` — data (here: the big lists of macOS defaults).
- **Module** — what a task calls to do the work. Uses **declarative**
  modules when possible: `osx_defaults` ("this key must be this value"),
  `git`, `get_url`, `homebrew` — you say the result, they figure out the
  diff. Pure commands (`nvram`, `pmset`...) stay `command`/`shell` tasks with
  `changed_when` guards since no dedicated module exists.
- **Become** — equivalent of sudo, only on the tasks that need it:
  `/Library/Preferences`, `scutil`, `nvram`, `pmset`... run per-task with
  `become: true`.
- **Check mode** — `--check --diff` shows what *would* change, touching
  nothing. Regular sanity-check for changes.
- **`-K`** — `--ask-become-pass`: asks for the sudo password (replaces the
  `sudo -v` keep-alive loop of the shell script).
- **Loop + `when`** — instead of repeating 100 lines of defaults, a task
  loops over a list of dicts (`vars/main.yml`); `when` guards optional or
  arch-dependent steps.

## Layout

```
macos-first-install/
├── bootstrap.sh                    # run this on a fresh machine
├── macos-first-install.yml         # playbook
├── Brewfile                        # generated by create-brewfile.sh
├── create-brewfile.sh              # dump installed packages to the Brewfile
└── roles/
    ├── macos_first_install/        # hostname, homebrew, Brewfile, defaults, pmset...
    │   ├── defaults/main.yml       # hostname + font list
    │   ├── vars/main.yml           # macOS defaults state lists
    │   └── tasks/*.yml
    └── dotfiles/
        ├── defaults/main.yml       # repo url + zsh plugins
        └── tasks/main.yml          # bare-clone, checkout, chsh...
```

## Fresh machine flow

## Fresh machine flow

1. Unbox, create your user account, connect to Wi-Fi. Nothing else;
2. `bootstrap.sh` then takes over:
   - Xcode command line tools (waits for the GUI installer),
   - Homebrew,
   - ansible, rust,
   - prompts for git identity only if `user.name`/`user.email` are unset
     globally,
   - `community.general` collection,
   - runs the playbook with `-K`.

## Day-to-day

- **Added packages by hand?** Update the Brewfile so the state stays
  recorded: `./create-brewfile.sh`. On any refreshed machine, it replays the
  same list.
- **Changed your system by hand?** Rerun the playbook — it converges back
  to the declared state.

## Usage

```sh
./bootstrap.sh                            # fresh machine
ansible-playbook macos-first-install.yml -K    # rerun / converge
ansible-playbook macos-first-install.yml -K --check --diff  # preview changes
```

## Extend

Want to change a system setting? Add one item to `vars/main.yml`:

```yaml
- {domain: com.apple.something, key: SomeKey, type: bool, value: true}
```

Rerun. Only that one line is applied, everything else reports `ok`.
